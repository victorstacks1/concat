# v0.2.8 Release CI Recovery Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the `v0.2.8` GitHub release so the Windows app can offer the update.

**Architecture:** Keep the release workflow's platform smoke gates intact. Correct the Android emulator graphics configuration and the iOS smoke check based on the observed logs, then rerun CI and publish the generated draft with the upstream base and source SHA in its notes.

**Tech Stack:** GitHub Actions, Bash, Android Emulator, Rust, GitHub Releases.

**Spec:** `.github/workflows/release.yml` (publish requires successful desktop and phone builds/smokes; draft release must be reviewed and published).

## Global Constraints

- Release version: `v0.2.8`.
- Release notes must state `Upstream base: v0.2.7` and `Origin commit: b5f9e01`.
- Do not update or install the app locally.
- Preserve the release gate requiring each bundled platform to pass its launch smoke.

## Review Focus

- Android API 30 emulator lacks the Vulkan adapter required by the app: verify the emulator's software GPU exposes Vulkan.
- Android API 35 remains a working control: confirm its smoke still passes.
- iOS simulator exits after logging `smoke: first frame rendered`: require a clean exit and that marker before continuing to the existing sustained-launch check.
- iOS sustained launch must still stay alive and emit the version log for the full configured observation interval.
- Release job must create only a draft until its notes and assets are reviewed.
